# AGENTS.md

Правила и контекст для агентов (и людей), работающих в этом репозитории.

## Что это за проект

DNS Profile Manager для Linux Mint 22 / Ubuntu 24.04 (NetworkManager + systemd-resolved).
Три интерфейса — GTK GUI (`dns-gui.py`), терминальное меню (`dns_menu.py`), CLI (`dnsctl` → `dns_manager.py`) — используют общий конфиг `.local/config/providers.json` и один механизм переключения (`shell/network.bash` через один вызов `sudo`).

## Критические ограничения

- **Никогда не выполнять команды, изменяющие DNS, сетевые настройки или системные файлы.**
  Запрещены: `nmcli connection modify`, `nmcli device reapply`, запись в `/etc/systemd/resolved.conf.d/*`, `sudo`, `systemctl restart/stop`, изменение `/etc/resolv.conf`.
  Разрешённые только read-only команды: `resolvectl dns|status|query`, `nmcli -g ... connection show`, `ip route`, `kdig`, `curl` (без переключения).
- **Не запускать unit-тесты самостоятельно.** По договорённости проекта тесты запускает пользователь (`/usr/bin/python3 -m unittest discover -s tests -v`). Агент может написать тесты и сообщить пользователю, что их нужно проверить.
- Тесты не должны переключать системный DNS: сетевой код проверяется через подменённый транспорт (`run`/`subprocess`), установщик — на `tempfile` и подменённых системных командах (см. существующие паттерны в `tests/`).
- Агенты не используют `sudo` и не запрашивают пароль пользователя.

## Структура

- `dns_manager.py` — общий движок: конфиг, состояние, `apply_profile`, проверки, CLI `main`.
- `dns_network.py` — типизированная машинная конфигурация `network.json`; Bash-переменные генерируются из данных.
- `dns_diagnostics.py` — HTTPS-измерения и сводки; сетевой код без GUI-зависимостей.
- `dns-gui.py` / `dns_checker.py` — GTK 3 фронтенды; сетевые операции всегда в фоновом потоке, обновление UI через `GLib.idle_add`.
- `dns_menu.py` — терминальное меню на `dialog`.
- `dns_setup.py` + `deployment/system.py` — транзакция установки/отката/удаления.
- `deployment/dispatcher.py` — root-owned Dispatcher; **не импортирует код из проекта или домашнего каталога**.
- `shell/*.bash` — сетевой backend и точка подключения CLI-команд.
- `.local/` — машинные настройки и данные, исключены из Git; не коммитить содержимое.
- `refactoring/REFACTORING_PLAN.md` — согласованный план рефакторинга; актуальность приоритетов проверять по датам в файле.

## Версии и релизы

- Версия в `VERSION`; CLI и GUI и меню — одна схема `MAJOR.MINOR.PATCH`; `README.md` держать в согласии с `VERSION`.
- История изменений — только в `CHANGELOG.md` в стиле Keep a Changelog, даты по Москве; при заметных изменениях добавлять запись в раздел `[Unreleased]` (Добавлено / Изменено / Исправлено / Проверено).

## Стиль кода

- Python 3.12 (`/usr/bin/python3`); зависимости — только системные пакеты (см. `deployment/system.py`: `PACKAGES`).
- Плотный однострочный стиль допускается в существующих модулях, но новые модули и тесты писать разборчиво; docstring на английском для публичных модулей, сообщения об ошибках и вывод — на русском.
- Тексты интерфейса на русском; gettext/i18n не вводить без согласованного решения.
- Команды провайдеров ограничены пространством `dns-*` / `xbox-dns-*`; ID — `[a-z][a-z0-9-]{0,39}`; проверяемые сервисы — `test_services` (см. `validate_config` в `dns_manager.py`).
- Bash в `shell/` не использует `eval` на пользовательских данных; привилегированная часть сериализует только известные переменные через `declare -p`.

## Проверки

- Синтаксис: `python3 -m py_compile` на изменённых модулях (не требует прав и не меняет сеть).
- Тесты: просит запускать пользователь (см. выше).
- Ручную проверку GUI — `./dns-gui` — выполняет пользователь; агент не запускать интерактивные приложения.
