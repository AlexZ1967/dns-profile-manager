# История изменений

Проект использует общую версию для CLI, терминального меню и GTK-интерфейса по схеме `MAJOR.MINOR.PATCH` (SemVer). Даты указаны по Москве. Первая зафиксированная версия — `1.0.0`; предшествующие изменения выполнялись без нумерации релизов.

## [1.2.2] — 2026-11-06

### Исправлено

- При откате частичного переключения DNS значения `--` от NetworkManager теперь нормализуются в пустые поля; ошибка чтения исходных DNS-параметров отменяет операцию до изменений.
- Добавлена регрессионная проверка отката с незаданным IPv6 DNS. Запуск тестов выполняет пользователь.

## [1.2.1] — 2026-11-06

### Исправлено

- Карточка статуса здоровья GUI строит Pango-разметку одним вызовом с экранированием текста.

### Изменено

- Кнопка возврата подписана «DNS от провайдера (DHCP)»; подтверждение объясняет, что адреса DNS будут получены от DHCP.

### Добавлено

- Отмена длительных операций в GUI: кнопка «Отмена» в диалоге прогресса («Статус DNS», «Подробности сети») и в панели проверки (check / check-all). Применение профиля не прерывается: это одна короткая привилегированная операция. Отмена работает по контрольным точкам: текущий этап завершается, новые не начинаются; частичные результаты не кэшируются.
- Проверки без переключения (`dnsctl check`, GUI, меню) берут общий пользовательский lock: вторая копия приложения получает то же сообщение «Другая операция DNS уже выполняется».
- Отличаются ошибки после переключения: «сверка состояния не удалась» (не удалось прочитать состояние) и «фактический DNS не совпадает» (реальное расхождение).

### Изменено

- Вывод отчёта в GUI буферизуется и вставляется пакетно (idle-приоритет по умолчанию), событие панели проверки обрабатывается в том же порядке; интерфейс не захлёбывается при «Проверить все».
- `AGENTS.md` с правилами для агентов: запрет операций, изменяющих DNS/сеть/системные файлы, запуск тестов пользователем, структура и стиль.
- Конфигурация статической проверки `ruff check` (`ruff.toml`); команда добавлена в «Проверки разработки».
- Маршруты CLI-команд (`commands.bash`) генерирует единственная функция, которую используют и CLI, и установщик.
- Формат миллисекунд один для CLI-отчётов и панели проверки GUI.
- `off_commands` ограничены 20 командами на провайдера.
- GUI перерисовывает карточку статуса только при изменении результатов проверки или соответствия профиля.
- shell/network.bash:
  - отсутствующий файл блокировки Dispatcher создаётся той же привилегированной операцией (открытие чтения-записи), симлинк-блокировка отклоняется;
  - при неудаче `nmcli connection modify` / `device reapply` / `systemctl restart` восстанавливаются прежние DNS-поля подключений и прежний конфиг resolved, после чего выполняется повторный restart;
  - `resolvectl flush-caches` после `systemctl restart systemd-resolved` удалён: restart и так сбрасывает кэш резолвера.

### Проверено

- Проверка локальной документации systemd 255 (Mint 22): формат `DNS=IP:порт` / `[IPv6]:порт` поддерживается, поэтому прежний пункт плана об ограничении портов снят (см. refactoring/REFACTORING_PLAN.md).

### Исправлено: единая авторизация переключения

- Повторный запрос пароля при переключении DNS в GUI: запись конфигурации, изменение DNS в NetworkManager и перезапуск resolved выполняются одним процессом через `sudo`, без предварительного `sudo -v` и вложенных запросов.
- CLI и GUI используют одну привилегированную операцию для ручных DNS и возврата к DHCP; сетевые подключения повторно проверяются после авторизации и захвата блокировки Dispatcher.
- Добавлены регрессионные проверки одного вызова `sudo` на операцию и отсутствия изменений при отмене авторизации. Запуск тестов выполняет пользователь.

## [1.2.0] — 2026-11-06

### Добавлено

- `./install` и `./uninstall` с предварительным просмотром `--dry-run`; установка зависимостей только с `--install-dependencies`.
- Установка на чистую машину с NetworkManager: автоматический список физических Ethernet/Wi-Fi подключений, опциональный выбор UUID через `--connection`, интеграция systemd-resolved и автономный root-owned Dispatcher.
- Сохранение пользовательских конфигов, кэша, резервных копий и журнала установки внутри `.local/` проекта; каталог исключён из Git.
- Перенос существующей ручной установки через `--adopt-existing`, сохранение исходных системных файлов и четырёх DNS-параметров подключений для отката неудачной установки.
- Удаление интеграции CLI/GUI/Bash, нового и перенесённого старого Dispatcher и DNS-профилей; очистка ручных DNS и включение DNS от DHCP у всех управляемых физических подключений. Прежние ручные DNS при удалении не возвращаются. Проект, конфиги, отчёты и резервные копии сохраняются; файлы других инструментов защищены.
- Изолированные тесты установки, отката, удаления, защиты чужих файлов и фильтрации VPN. Запуск выполняет пользователь.

### Изменено

- Кнопка «Диагностика сети» переименована в «Статус DNS», чтобы обозначить соответствие команде `dns-status`.
- CLI, GUI и Bash используют общий `network.json`; поддерживаются машины с одним физическим подключением и с несколькими.
- Переключение и установка используют общие блокировки; перенос проекта на другую машину требует повторной установки, удалённая интеграция не воссоздаётся из старого открытого окна.

### Проверка

- Выполнена статическая проверка синтаксиса. Пользователь подтвердил успешное выполнение всех тестов и ручную проверку установки/удаления.

## [1.1.1] — 2026-11-06

### Изменено

- DNS-команды и сетевые функции вынесены из общего `~/.bash_aliases` в модули проекта `shell/dns.bash` и `shell/network.bash`.
- В общем файле Bash остаётся только одно защищённое подключение модуля; остальные команды сохраняются при миграции.
- UUID, имена интерфейсов и существующие локальные пути перенесены в пользовательский `~/.config/dns-manager/network.bash`, не входящий в Git.
- CLI и GUI загружают сетевой модуль напрямую, без выполнения общего файла aliases.
- Установщик сохраняет резервную копию, проверяет границы DNS-раздела и останавливается при неизвестных командах или конфликте локальных настроек; повторный запуск не перезаписывает общий файл без изменений.
- Тесты сетевого модуля переведены на изолированные настройки; добавлены проверки миграции, сохранения посторонних команд и независимости runtime от aliases. Запуск выполняет пользователь.

### Проверено

- Пользователь подтвердил успешное выполнение тестов версии 1.1.1.

## [1.1.0] — 2026-11-06

### Добавлено

- Отдельная GTK-панель проверки профиля с тёмным оформлением, карточками сервисов, фактическим прогрессом, сводными метриками и кнопкой «Проверить снова».
- Диагностика Claude, Gemini, ChatGPT, Perplexity, Google AI Studio, Antigravity и контрольного GitHub.
- Измерение этапов DNS, TCP, TLS, первого байта и полного HTTPS-запроса; HTTP-коды и причины ограничений по каждому сервису.
- Проверка HTTPS-перенаправлений с разрешением каждого нового домена через выбранный DNS-профиль, без перехода на системный DNS.
- Обработка Cloudflare Challenge, HTTP 403/429, региональных сообщений, циклов редиректов и ошибок сертификата.
- Настраиваемый список `test_services` в общем конфиге, совместимость со старым `test_domains` и команда `dnsctl config upgrade-checks`.
- Подробные результаты и сводка сервисов в CLI/JSON и терминальном меню; учёт схемы диагностики и списка сервисов в кэше.
- Регрессионные тесты измерений, HTTP-ограничений, TLS, редиректов и обновления конфигурации. Запуск тестов выполняет пользователь.

### Изменено

- Интерфейс проверки показывает состояние проверяемого профиля отдельно от системного DNS.
- Успешным считается проверенный HTTPS-ответ 2xx после допустимой цепочки перенаправлений; один ответ 3xx больше не считается достаточным.
- Сетевые измерения не преобразуются в искусственный RTT и не подтверждают отсутствие CAPTCHA после входа в аккаунт.

### Проверено

- Пользователь подтвердил успешное выполнение тестов и проверку GUI версии 1.1.0.

## [1.0.0] — 2026-11-06

### Добавлено

- Общий JSON-конфиг провайдеров для CLI и GUI: адреса, протокол, TLS-имя, порт, описание, сайт и имена команд.
- Профили DNS провайдера, MagicDNS, Dagami DNS, Xbox Smart DNS и DNS-AI.
- Команда `dnsctl`: список провайдеров, фактическое состояние, применение профиля, диагностика, проверка и управление конфигурацией.
- GTK-интерфейс с редактированием и добавлением провайдеров, прогрессом, отчётом и быстрым возвратом к DHCP DNS.
- Терминальное меню с общей конфигурацией и диагностикой.
- Прямые проверки DNS и HTTPS без переключения системного DNS, с зелёным, жёлтым, красным и неопределённым статусами.
- Проверка сертификата и TLS-имени для DoT; HTTPS по адресу из ответа проверяемого DNS с сохранением имени сайта и проверки сертификата.
- Автоматическое создание CLI-команд при добавлении провайдера; валидация конфигурации и защита существующих команд от перезаписи.
- Кэш результатов, учитывающий сеть, возраст проверки, настройки провайдера и DHCP DNS.
- Интеграция с существующими Bash-функциями Ethernet/Wi-Fi, резервная копия aliases и согласование блокировок с Dispatcher v2.
- Общий файл `VERSION`, вывод `--version` и документация по запуску и настройке.
- 16 автоматизированных проверок конфигурации, команд, диагностики, сетевых функций с подменёнными системными командами и поведения терминального буфера.

### Исправлено

- Определение активного профиля после перехода CLI на глобальный DNS и несколько активных подключений.
- Использование устаревшей переменной фиксированного подключения и старого TLS-имени MagicDNS в интерфейсах.
- Перехват Bash-команды `read`, конфликтовавший с перебором активных подключений.
- Пиксельные шрифты прежнего Tk-интерфейса: GUI переведён на системный GTK/Pango.
- Попадание кадров терминального меню в историю прокрутки и случайное закрытие отчёта мышью.
- Разбор DHCP-опций, различение DNS и HTTPS-ошибок, обработка HTTP 403 и устаревших результатов.

### Ограничения

- Интеграция рассчитана на уже настроенные Bash-функции NetworkManager/systemd-resolved; универсального установщика для чистой системы пока нет.
- Применяются DHCP, обычный DNS и DoT. Нативное применение DoH не реализовано.
- Диагностика HTTPS проверяет выбранные IPv4-адреса из текущей сети и не подтверждает доступность всех функций сайтов.
