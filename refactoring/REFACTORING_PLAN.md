# План рефакторинга DNS Profile Manager

> Дата анализа: 2026-11-06. Версия проекта: 1.2.1.
> Ограничения: разработка не должна изменять DNS, сетевые настройки и системные файлы; запуск тестов — по соглашению проекта выполняет пользователь.

## 1. AGENTS.md

- При первичном анализе файла не было; в ходе PR-1 он создан в корне проекта.
- `AGENTS.md` фиксирует запрет агенту менять сетевые и системные настройки, запускать тесты или запрашивать sudo; описывает архитектуру и разрешённые статические проверки.

## 2. Архитектура (итог анализа)

- Общий движок: `dns_manager.py` (конфиг, состояние, применение, проверки, CLI), `dns_network.py` (network.json), `dns_diagnostics.py` (HTTPS-зонды), `shell/network.bash` (сетевой backend).
- Интерфейсы: `dns-gui.py` (GTK 3) + `dns_checker.py` (панель диагностики), `dns_menu.py` (dialog), `dnsctl` + `shell/dns.bash` (CLI/Bash).
- Системная часть: `dns_setup.py`, `deployment/system.py` (транзакции установки/отката), `deployment/dispatcher.py` (root-owned Dispatcher).

## 3. Существующий код переключения (для контекста)

`apply_profile` (dns_manager.py:382) → lock `.local/cache/operation.lock` → bash + `shell/network.bash` → один `sudo` (`_dns_privileged_apply`) → `_dns_apply_as_root` (flock Dispatcher, повторная проверка подключений, атомарная запись resolved-конфа) → `_dns_nm_configure` (nmcli modify + device reapply) → `systemctl restart systemd-resolved` + flush → верификация через `current_state`.

## 4. Задачи рефакторинга

### Высокий приоритет

1. **Откат при частичном отказе `_dns_nm_configure`** (shell/network.bash) — ✅ выполнено 2026-11-06
   - Проблема: при неудаче `nmcli connection modify`/`device reapply` глобальный конфиг resolved уже записан или изменён; система остаётся в рассогласованном состоянии до ручного вмешательства.
   - Сделать: сохранить прежний конфиг resolved; при неудаче последнего этапа восстановить изменённые поля подключений и конфиг (или явно вычистить частично изменённые подключения).

2. **Пер-серверные порты** (dns_manager.py:288 `server_tokens`, валидация порта)
   - Снято 2026-11-06 по проверке: локальная документация systemd 255 (Mint 22) подтверждает формат `DNS=IP:port` и `[IPv6]:port#SNI` в `resolved.conf`; тест `server_tokens` с `port=8853` корректен. Изменение кода не требуется.

3. **Условный lock в `_dns_apply_as_root`** — ✅ выполнено 2026-11-06
   - Проблема: flock берётся только если файл `/run/lock/nm-dns-primary-route.lock` уже существует (`[[ -e ]]`, без `O_CREAT`); без установленного Dispatcher взаимное исключение молча отсутствует.
   - Сделать: создавать lock-файл явно (root может) или логировать его отсутствие.

4. **`systemctl restart systemd-resolved` + два flush** — ✅ выполнено 2026-11-06 (flush удалён)
   - Проблема: restart кратковременно прерывает резолвинг для всех приложений; `flush-caches` после restart избыточен.
   - Сделать: пересмотреть на `try-restart`/reconfigure и убрать избыточный `flush-caches` при успешном restart.

### Средний приоритет — GUI

5. **Кнопка «Отмена» для длительных операций** (dns-gui.py: `_show_progress`, `_start_task`): progress-диалог без ответных кнопок; для check-операций сеть может «висеть» до суммарного таймаута. Добавить флаг отмены/завершение потока. — ✅ выполнено 2026-11-06: кнопка «Отмена» в диалоге прогресса (status/details) и в панели проверки (check/check-all, `should_stop` и контрольные точки в `check_provider`/`diagnostic`); `apply` не прерывается (одна короткая привилегированная операция).

6. **Опрос конфига каждые 5 с** (`_watch_config`) — сейчас это серия subprocess (nmcli × N + resolvectl) на каждом обновлении. Перейти на файловый монитор GLib для каталога конфига (debounce 800 мс), тогда как изменение сети (DHCP DNS, маршрут) не является изменением файлов. — ✅ выполнено 2026-11-06: монитор `CONFIG.parent` + медленный обновитель состояния раз в 20 с.

7. **Markup `health_label`** — ✅ выполнено 2026-11-06: итоговая разметка строится один раз, текст результата экранируется отдельно от цвета.

8. **Приоритет `GLib.idle_add`** → `PRIORITY_DEFAULT_IDLE` + батчинг вставок в буфер при `check-all`, чтобы не захлёбывался рендер при выводе 50 провайдеров подряд. — ✅ выполнено 2026-11-06: emit-линии с плечами буферизации `_pending_report`/`_flush_report` (150 мс), idle-приоритеты для отчёта и событий чекера.

9. **Единая тема**: основное окно светлое, чекер тёмный; привести к единому стилю или учитывать системную тёмную тему. — 🔒 отложено: требует дизайн-решения (единая палитра или осознанное разделение «документ/панель»). Обе темы сейчас статичны и согласованы внутри себя; трогать без макета не стал.

### Средний приоритет — конкуренция и UX

12. **GUI: возврат к DHCP** — ✅ выполнено 2026-11-06: кнопка подписана «DNS от провайдера (DHCP)», подтверждение явно сообщает, что адреса будут получены по DHCP.
