# DNS Profile Manager

Текущая версия: **1.0.0**. История изменений — [CHANGELOG.md](CHANGELOG.md). Номер релиза хранится в [VERSION](VERSION); CLI и GUI используют одну версию по схеме `MAJOR.MINOR.PATCH`.

Менеджер DNS для Linux Mint / NetworkManager / systemd-resolved: CLI, терминальное меню и GTK-интерфейс используют общую конфигурацию и один механизм переключения.

## Запуск

```bash
./dns-gui          # GTK-интерфейс
./dns-menu         # терминальное меню
./dnsctl --version # версия приложения
./dnsctl list      # список провайдеров и CLI-команд
./dnsctl current   # фактический DNS и основной маршрут
```

Приложение использует системный `/usr/bin/python3` с PyGObject / GTK 3 / Pango. Также нужны NetworkManager, systemd-resolved, curl, kdig; для терминального меню — dialog, для графического запроса пароля — zenity. Зависимости автоматически не устанавливаются.

## Общий конфиг

Рабочий файл: `~/.config/dns-manager/providers.json`.

`providers.default.json` — начальный шаблон; после установки изменения вносятся в рабочий файл. В нём находятся IP-адреса, протокол, порт, TLS-имя, название, описание, сайт и CLI-команды каждого провайдера. Режимы: `dhcp`, `dot`, `plain`. Нативного применения DoH здесь нет: systemd-resolved используется с DoT либо обычным DNS.

В GUI выберите провайдера → **Настроить**, либо **Добавить провайдера**. Сохранение не переключает DNS. Для применения используется отдельная кнопка. Настройки DHCP-провайдера не содержат ручных адресов.

Пример нового провайдера:

```json
{
  "id": "example",
  "name": "Example DNS",
  "mode": "dot",
  "servers": ["203.0.113.10"],
  "tls_hostname": "dns.example.org",
  "port": 853,
  "command": "dns-example-on",
  "off_commands": ["dns-example-off"],
  "website": "https://example.org/",
  "description": "Пример структуры, адрес не является рабочим DNS"
}
```

При сохранении через GUI или CLI импорта автоматически обновляются `commands.bash` и команды в `~/.local/bin`. Новый провайдер появляется в обоих интерфейсах. CLI-команды читают параметры из JSON при каждом вызове.

```bash
./dnsctl config path
./dnsctl config show
./dnsctl config import /путь/к/providers.json
./dnsctl config sync-commands  # после ручного редактирования JSON
```

Имена ограничены пространством `dns-*` / `xbox-dns-*`; существующие посторонние команды не перезаписываются. Для обновления функций в уже открытом Bash выполните `source ~/.bash_aliases`. Новые исполняемые команды доступны через `~/.local/bin`, если он есть в PATH.

## CLI

Сохранены команды `dns-provider`, `dns-magic-on/off`, `dns-dagami-on/off`, `dns-ai-on/off`, `xbox-dns-on/off`, `dns-status`, `dns-details`. `dns-ai-update` остаётся отдельной командой скачивания установщика; применение DNS-AI его не запускает.

```bash
./dnsctl apply magic
./dnsctl apply dagami
./dnsctl apply provider
./dnsctl status
./dnsctl details
./dnsctl check ai
./dnsctl check --all
./dnsctl check --all --json
# Аналогично после подключения команд:
dns-check magic
dns-check --all
```

`apply` меняет DNS. **`check` не изменяет DNS и не требует sudo.** Код завершения `check`: 0 — все проверки успешны, 1 — есть частичные/неуспешные результаты, 2 — ошибка выполнения. В режиме JSON возвращается список подробных результатов.

## Проверка без переключения

Запросы отправляются непосредственно каждому IP из конфигурации. Для DoT проверяются цепочка сертификата, TLS-имя и SNI; незаметного перехода на незашифрованный DNS нет. В DHCP-режиме адреса читаются из DHCP активных известных подключений, даже когда системно выбран другой профиль.

Для `chatgpt.com`, `github.com`, `gemini.google.com` запрашиваются A-записи. Затем HTTPS проверяется через `curl --resolve` по адресу из ответа этого провайдера с исходным именем сайта, проверкой сертификата и без прокси. Проверяется первый IPv4 из каждого ответа сервера, одинаковые пары домен/IP объединяются. Переадресации HTTP не обходятся автоматически; ответ 2xx/3xx означает доступность исходного HTTPS-адреса, а не всех функций сайта или учётной записи.

- **Зелёная ✓:** все серверы отвечают для тестовых доменов, проверенные HTTPS-адреса возвращают 2xx/3xx.
- **Жёлтая ⚠:** работает часть серверов/доменов либо DNS отвечает, но HTTPS ограничен/недоступен. HTTP 403 — ограничение доступа, а не успешный доступ к сайту.
- **Красная ✕:** ни один сервер не вернул пригодный DNS-ответ для тестовых доменов.
- **Серая ○:** проверка не выполнена, устарела или отсутствует инструмент проверки.

Причина показывается у выбранного провайдера, в подсказке значка и полном отчёте. Все запросы ограничены по времени. Статус относится к текущему маршруту; кэш в `~/.cache/dns-manager/health.json` устаревает через 15 минут, при смене сети, изменении DHCP DNS или конфигурации провайдера. Проверки не отключают интерфейсы для тестирования другой сети.

## Согласование с установленными Bash-скриптами

`integrate.py` предназначен для уже настроенной версии `~/.bash_aliases` с `_dns_active_connections`, `_dns_nm_configure`, `_dns_switch`. Он сохраняет резервную копию в `~/.config/dns-manager/backups/`, сохраняет функции VS Code / Xray и существующий список UUID Ethernet/Wi-Fi. Неожиданная версия aliases не заменяется автоматически.

Переключение делегируется установленным Bash-функциям. Они меняют только активные известные подключения и используют `nmcli device reapply`. Глобальные DoT/обычные DNS записываются в `/etc/systemd/resolved.conf.d/90-alex-dns-profile.conf`; DHCP возвращается удалением управляемого профиля. Xbox также использует глобальный обычный DNS, что соответствует Dispatcher v2.

Операции CLI/GUI блокируются общим пользовательским lock. Bash-переключение после авторизации получает lock существующего Dispatcher `/run/lock/nm-dns-primary-route.lock`; конфиг resolved заменяется атомарно. Метрики маршрутов, VPN, прокси-переменные и неактивные подключения не изменяются. Сам системный Dispatcher при интеграции не редактируется. GUI работает от обычного пользователя; sudo применяется только там, где он нужен существующим Bash-функциям.

## Проверки разработки

```bash
/usr/bin/python3 -m unittest discover -s tests -v
```

Тесты проверяют конфигурацию, создание команд, блокировки, актуальность статусов, прямые DNS/TLS/HTTPS-запросы с подменённым транспортом и применение к Ethernet/Wi-Fi с подменённым nmcli. Они не переключают системный DNS.
